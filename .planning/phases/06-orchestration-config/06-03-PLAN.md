**`crates/core/src/orchestrate/cache.rs`:**

1. Create `PipelineCacheKey` — content-addressed key for the pipeline cache:
```rust
use std::hash::{Hash, Hasher};
use foldhash::fast::FixedState;

#[derive(Debug, Clone, PartialEq, Eq, Hash)]
pub struct PipelineCacheKey {
    hash: u64,
}

impl PipelineCacheKey {
    /// Create a cache key from source text, target text, and a config fingerprint.
    pub fn new(source: &str, target: &str, config_fingerprint: u64) -> Self {
        let state = FixedState::with_seed(0);
        let mut hasher = state.build_hasher();
        source.hash(&mut hasher);
        target.hash(&mut hasher);
        config_fingerprint.hash(&mut hasher);
        Self { hash: hasher.finish() }
    }
}
```

Note: `FixedState::with_seed(0)` follows the same deterministic hashing pattern used in `crate::metrics::cache::ContentHash`. Import `foldhash::fast::FixedState` and `std::hash::BuildHasher`.

2. Create a config fingerprint function that hashes the configuration for cache key differentiation:
```rust
pub(crate) fn config_fingerprint(config: &RedlineConfig) -> u64 {
    let state = FixedState::with_seed(0);
    let mut hasher = state.build_hasher();
    // Hash preset
    (config.preset as u8).hash(&mut hasher);
    // Hash boolean flags
    config.metrics_enabled.hash(&mut hasher);
    config.analysis_enabled.hash(&mut hasher);
    // Hash execution mode (as u8)
    (config.execution_mode as u8).hash(&mut hasher);
    hasher.finish()
}
```

Note: We hash preset + flags rather than normalizer/tokenizer names to keep it simple. Different presets always have different fingerprints. Custom normalizers/tokenizers are an edge case where users must manage cache invalidation themselves.

3. Create `CachedResult` — the value stored in the cache:
```rust
use std::sync::Arc;

/// A cached pipeline result wrapped in Arc for cheap cloning out of the cache.
#[derive(Debug, Clone)]
pub(crate) struct CachedResult {
    pub(crate) diff: DiffResult,
    pub(crate) metrics: HashMap<String, MetricValue>,
    pub(crate) analysis: Option<Arc<AnalysisReport>>,
    /// Estimated memory usage in bytes (for optional memory cap).
    pub(crate) estimated_bytes: usize,
}
```

Important: `AnalysisReport` is `!Clone` because it contains `Box<dyn Any + Send + Sync>`. Wrap it in `Arc<AnalysisReport>` to enable sharing cached results. `DiffResult` is `Clone` (already verified by `assert_impl_all!`). `MetricValue` is `Clone`. So `CachedResult` is Clone when AnalysisReport is wrapped in Arc.

Add a helper to estimate memory:
```rust
impl CachedResult {
    pub(crate) fn estimate_memory(diff: &DiffResult, metrics: &HashMap<String, MetricValue>, has_analysis: bool) -> usize {
        let ops_bytes = diff.operations.len() * std::mem::size_of::<EditOperation>();
        let source_bytes = diff.source.original.len() + diff.source.normalized.len();
        let target_bytes = diff.target.original.len() + diff.target.normalized.len();
        let metrics_bytes = metrics.len() * 64; // rough estimate per entry
        let analysis_bytes = if has_analysis { 4096 } else { 0 }; // rough fixed overhead
        ops_bytes + source_bytes + target_bytes + metrics_bytes + analysis_bytes + 256 // struct overhead
    }
}
```

4. Create `CacheManager`:
```rust
use parking_lot::RwLock;
use lru::LruCache;
use std::num::NonZeroUsize;

pub struct CacheManager {
    cache: RwLock<LruCache<PipelineCacheKey, CachedResult>>,
    memory_limit: Option<usize>,
    total_bytes: RwLock<usize>,
}
```

Implement methods:
- `pub fn new(capacity: usize) -> Self` — create with entry-count LRU, no memory limit. Use `NonZeroUsize::new(capacity).expect("cache capacity must be > 0")`.
- `pub fn with_memory_limit(capacity: usize, limit: usize) -> Self` — with optional memory cap.
- `pub fn get(&self, key: &PipelineCacheKey) -> Option<CachedResult>` — acquire WRITE lock (LRU get updates ordering), clone and return. This is a write lock because `lru::LruCache::get()` mutates the internal order.
- `pub fn insert(&self, key: PipelineCacheKey, value: CachedResult)` — acquire write lock, insert. If memory limit is set and total_bytes exceeds it, evict LRU entries until under limit.
- `pub fn clear(&self)` — acquire write lock, clear cache and reset total_bytes.
- `pub fn len(&self) -> usize` — read lock on cache, return len.
- `pub fn is_empty(&self) -> bool`
- `pub fn total_memory(&self) -> usize` — return *total_bytes value.

**Memory cap eviction in `insert()`:**
After inserting, if memory_limit is Some(limit):
```rust
let mut bytes = self.total_bytes.write();
*bytes += value.estimated_bytes;
if let Some(limit) = self.memory_limit {
    let mut cache = self.cache.write();
    while *bytes > limit {
        if let Some((_, evicted)) = cache.pop_lru() {
            *bytes = bytes.saturating_sub(evicted.estimated_bytes);
        } else {
            break;
        }
    }
}
```

Actually, to avoid double-locking, restructure: hold the cache write lock for the entire insert+evict operation. Do NOT hold separate locks on total_bytes and cache simultaneously to avoid deadlock — use a single lock on cache and track total_bytes as an atomic or inside the same lock.

**Revised approach (simpler, no deadlock risk):**
```rust
pub struct CacheManager {
    inner: RwLock<CacheInner>,
    memory_limit: Option<usize>,
}

struct CacheInner {
    cache: LruCache<PipelineCacheKey, CachedResult>,
    total_bytes: usize,
}
```

All operations take a single lock on `inner`. This is simpler and eliminates any deadlock possibility.
