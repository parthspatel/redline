**Implement SentenceTokenizer:**

```rust
use unicode_segmentation::UnicodeSegmentation;

impl Tokenizer for SentenceTokenizer {
    fn tokenize(
        &self,
        text: &str,
        _mapping: &CharMapping,
        store: &mut TextStoreBuilder,
    ) -> Result<Vec<Token>, TokenizeError> {
        if text.is_empty() {
            return Ok(vec![]);
        }

        let mut tokens = Vec::new();
        for (byte_offset, sentence_segment) in text.split_sentence_bound_indices() {
            // Filter: only include segments with at least one alphanumeric character
            // This matches unicode_sentences() behavior but preserves byte offsets
            if !sentence_segment.chars().any(|c| c.is_alphanumeric()) {
                continue;
            }
            // Trim trailing whitespace from the sentence for cleaner tokens,
            // but keep the span pointing to the full segment for position accuracy
            let trimmed = sentence_segment.trim_end();
            if trimmed.is_empty() {
                continue;
            }
            let text_id = store.intern(trimmed);
            let span = Span::new(
                byte_offset as u32,
                (byte_offset + trimmed.len()) as u32,
            );
            tokens.push(Token::new(text_id, span, TokenKind::Regular));
        }
        Ok(tokens)
    }

    fn name(&self) -> &str { "sentence" }
}
```

Key design decisions:
- Uses `split_sentence_bound_indices()` (NOT `unicode_sentences()`) to get byte offsets directly.
- Filters segments to those containing alphanumeric characters (matching `unicode_sentences` filtering).
- Trims trailing whitespace from token text so "Hello. " becomes token text "Hello." with span covering only "Hello." bytes.
- UAX#29 handles abbreviations and decimals as well as the standard allows.

**Implement WordNGramTokenizer:**

```rust
impl Tokenizer for WordNGramTokenizer {
    fn tokenize(
        &self,
        text: &str,
        mapping: &CharMapping,
        store: &mut TextStoreBuilder,
    ) -> Result<Vec<Token>, TokenizeError> {
        if text.is_empty() {
            return Ok(vec![]);
        }

        // Run base tokenizer first
        let base_tokens = self.base.tokenize(text, mapping, store)?;

        if base_tokens.len() < self.n {
            return Ok(vec![]);
        }

        let mut ngram_tokens = Vec::with_capacity(base_tokens.len() - self.n + 1);

        for window in base_tokens.windows(self.n) {
            // Merged span: from first token's start to last token's end
            let span = Span::new(
                window.first().unwrap().span.start(),
                window.last().unwrap().span.end(),
            );

            // Build n-gram text by resolving and joining base token texts
            let ngram_text: String = window
                .iter()
                .map(|t| store.resolve(t.text_id).unwrap())
                .collect::<Vec<&str>>()
                .join(" ");

            let text_id = store.intern(&ngram_text);
            ngram_tokens.push(Token::new(text_id, span, TokenKind::Regular));
        }

        Ok(ngram_tokens)
    }

    fn name(&self) -> &str { &self.name }
}
```

Key design decisions:
- Runs base tokenizer first, then slides window of size `n` over base tokens.
- N-gram text is space-joined from resolved base token texts (new StringIds per research recommendation).
- Span merges first-to-last token span, covering gaps (Pitfall 6 from research).
- If base produces fewer than `n` tokens, returns empty vec (not an error).

**Implement CharNGramTokenizer (composable wrapper, mirrors WordNGramTokenizer):**

```rust
impl Tokenizer for CharNGramTokenizer {
    fn tokenize(
        &self,
        text: &str,
        mapping: &CharMapping,
        store: &mut TextStoreBuilder,
    ) -> Result<Vec<Token>, TokenizeError> {
        if text.is_empty() {
            return Ok(vec![]);
        }

        // Run base tokenizer first (default: CharTokenizer producing 1 token per grapheme)
        let base_tokens = self.base.tokenize(text, mapping, store)?;

        if base_tokens.len() < self.n {
            return Ok(vec![]);
        }

        let mut ngram_tokens = Vec::with_capacity(base_tokens.len() - self.n + 1);

        for window in base_tokens.windows(self.n) {
            // Merged span: from first token's start to last token's end
            let span = Span::new(
                window.first().unwrap().span.start(),
                window.last().unwrap().span.end(),
            );

            // N-gram text is the direct substring from the text (contiguous characters)
            let start = span.start() as usize;
            let end = span.end() as usize;
            let ngram_text = &text[start..end];
            let text_id = store.intern(ngram_text);
            ngram_tokens.push(Token::new(text_id, span, TokenKind::Regular));
        }

        Ok(ngram_tokens)
    }

    fn name(&self) -> &str { &self.name }
}
```

Key design decisions:
- Wraps a base tokenizer (default: CharTokenizer) per CONTEXT.md locked decision on composability.
- Mirrors WordNGramTokenizer's pattern: run base first, slide n-window over base tokens.
- N-gram text is the direct substring from text (contiguous chars), not space-joined like WordNGramTokenizer.
- Span merges first-to-last token span. Since CharTokenizer produces contiguous grapheme tokens, the span exactly covers the n-gram substring.
