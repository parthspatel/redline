  <behavior>
    All metrics operate on token sequences via `StringId` comparison (not raw text). Extract `Vec<StringId>` from `source.tokens` and `target.tokens`.

    **LevenshteinDistanceMetric** (id: "levenshtein_distance"):
    - Classic DP edit distance on token sequences.
    - Operations: insert, delete, substitute (each cost 1).
    - Optimization: only keep two rows (O(min(n,m)) space).
    - Returns Integer.
    - Identical sequences -> 0.

    **DamerauLevenshteinDistanceMetric** (id: "damerau_levenshtein"):
    - Like Levenshtein but also allows transposition (swap adjacent tokens, cost 1).
    - Use optimal string alignment (restricted edit distance) variant.
    - "a b" vs "b a" -> 1 (transposition), Levenshtein would be 2.
    - Returns Integer.

    **HammingDistanceMetric** (id: "hamming_distance"):
    - Count positions where tokens differ. Only defined for equal-length sequences.
    - If lengths differ, return `Err(MetricError::InvalidInput("hamming requires equal-length sequences"))`.
    - Returns Integer.

    **JaroSimilarityMetric** (id: "jaro_similarity"):
    - Jaro algorithm adapted for token sequences:
      1. Match window = `max(|s|, |t|) / 2 - 1`, min 0.
      2. Count matching tokens (same StringId within window).
      3. Count transpositions.
      4. `jaro = (m/|s| + m/|t| + (m-t/2)/m) / 3`
    - Returns Float in [0.0, 1.0].
    - Both empty -> 1.0.

    **JaroWinklerSimilarityMetric** (id: "jaro_winkler_similarity"):
    - Depends on "jaro_similarity" via static dependency system.
    - `jaro_winkler = jaro + l * p * (1 - jaro)` where l = common prefix length (up to 4), p = 0.1.
    - Returns Float in [0.0, 1.0].
    - Result >= jaro.

    **Property tests:**
    - levenshtein(a, a) == 0
    - levenshtein(a, b) >= 0
    - levenshtein(a, b) == levenshtein(b, a) (symmetry)
    - jaro in [0.0, 1.0]
    - jaro_winkler >= jaro (for same input)
  </behavior>
  <implementation>
    1. Each metric in its own file within `similarity/`.
    2. Extract token StringIds as `Vec<StringId>` for DP algorithms.
    3. Levenshtein: two-row DP optimization.
    4. Damerau-Levenshtein: three-row DP for transpositions.
    5. Jaro: standard matching algorithm with boolean "matched" arrays.
    6. JaroWinkler: depends on jaro_similarity via dependency system.
    7. Update `similarity/mod.rs` with new module declarations.
  </implementation>
</feature>
