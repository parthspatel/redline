# Plan 02.1-01: Core Type Edge Case Tests

**Objective:** Add comprehensive edge case tests to Phase 1 core types — Span, Token, TextStore, CharMapping, and Error. Focus on boundary conditions, error paths, and Unicode edge cases.

## must_haves

- Every public method on Span has at least one boundary/edge case test
- Token construction with extreme values (max u32 offsets, all TokenKind variants)
- TextStore: empty string interning, duplicate interning, large string interning, resolve after Arc promotion
- CharMapping: single-entry mapping, very large mappings, compose with single entries, original_len correctness
- Error types: Display/Debug output verification, From conversions

## Tasks

<task id="1" type="execute">
**Add edge case tests to core types**

Read each file first, then add tests to the existing `#[cfg(test)]` blocks.

**Span (span.rs) — add these edge cases:**
- `Span::new(0, 0)` — zero-length span at start
- `Span::new(u32::MAX - 1, u32::MAX)` — span at max offset
- `contains()` at exact boundaries (start inclusive, end exclusive)
- `overlaps()` with adjacent non-overlapping spans (end == start)
- `merge()` of non-overlapping spans
- `split()` at start, end, and middle
- `len()` returns 0 for empty span

**Token (token.rs) — add these edge cases:**
- Construction with StringId(0), StringId(u32::MAX)
- All TokenKind variants via `is_special()`, `is_continuation()`, `is_unknown()`
- Token with zero-length span
- Token equality: same content different span, same span different StringId

**TextStore (text_store.rs) — add these edge cases:**
- Intern empty string `""`
- Intern same string twice returns same StringId
- Intern single char, including multi-byte Unicode (emoji, CJK)
- Intern very long string (10KB+)
- Resolve with invalid StringId after Arc promotion
- Resolve all strings after Arc promotion from TextStoreBuilder
- Builder len() tracking accuracy

**CharMapping (char_mapping.rs) — add these edge cases:**
- `CharMapping::new()` with single alignment pair
- `CharMapping::identity(1)` — single-char text
- `to_original()` / `to_normalized()` with exact first/last positions
- `to_normalized_nearest()` with position before all entries, between entries, after all entries
- `compose()` of two identity mappings
- `compose()` of single-entry mappings
- `original_len()` correctness after identity, new, and compose
- Very large mapping (1000 entries) lookups

**Error (error.rs) — add these edge cases:**
- All error variant Display strings are non-empty
- Specific Display format assertions for key variants
- NormalizeError::InvalidPosition stores correct position value

</task>
