# Plan 02.1-05: Deterministic Simulation Testing

**Objective:** Create seed-based deterministic simulation tests using proptest that exercise the full pipeline with randomized normalizer/tokenizer combinations, random Unicode input, and full reproducibility via seeds.

## must_haves

- Simulation test file with proptest-based deterministic scenarios
- Random normalizer subset selection (1-4 normalizers from pool of 6)
- Random tokenizer selection (1 of 5)
- Random Unicode input generation (varying lengths, scripts, special chars)
- Full pipeline execution with validity assertions
- Seed-based reproducibility: `PROPTEST_CASES=10000 cargo test --test simulation` discovers edge cases
- Any failure reproducible via proptest regression files
- CharMapping composition validated through arbitrary normalizer chains
- Span bounds validated for all tokens against original input length

**Key design: leverage proptest's seeded infrastructure**

Proptest already provides:
- Deterministic seed-based generation (`PROPTEST_CASES`, `PROPTEST_MAX_SHRINK_ITERS`)
- Automatic regression files (`.proptest-regressions/`) for replay
- Custom strategies for complex type generation

**Simulation strategies to implement:**

```rust
use proptest::prelude::*;

/// Strategy that generates a random subset of normalizers (1-4)
fn normalizer_subset() -> impl Strategy<Value = Vec<Box<dyn Normalizer>>> {
    // Use prop::sample::subsequence to pick from the 6 available normalizers
    // Each normalizer identified by index 0-5:
    // 0=Lowercase, 1=Whitespace, 2=UnicodeNFC, 3=Diacritics, 4=Punctuation, 5=Digits
    prop::collection::vec(0u8..6, 1..=4)
        .prop_map(|indices| {
            let mut seen = std::collections::HashSet::new();
            indices.into_iter()
                .filter(|i| seen.insert(*i))
                .map(|i| match i {
                    0 => Box::new(Lowercase) as Box<dyn Normalizer>,
                    1 => Box::new(WhitespaceNormalizer) as Box<dyn Normalizer>,
                    2 => Box::new(UnicodeNormalizer::default()) as Box<dyn Normalizer>,
                    3 => Box::new(RemoveDiacritics) as Box<dyn Normalizer>,
                    4 => Box::new(RemovePunctuation) as Box<dyn Normalizer>,
                    _ => Box::new(RemoveDigits) as Box<dyn Normalizer>,
                })
                .collect()
        })
}

/// Strategy that picks a random tokenizer (excluding n-gram variants for simplicity)
fn tokenizer_choice() -> impl Strategy<Value = Box<dyn Tokenizer>> {
    prop::sample::select(vec![0u8, 1, 2]).prop_map(|i| match i {
        0 => Box::new(CharTokenizer) as Box<dyn Tokenizer>,
        1 => Box::new(WordTokenizer) as Box<dyn Tokenizer>,
        _ => Box::new(SentenceTokenizer) as Box<dyn Tokenizer>,
    })
}
```

NOTE: The above is pseudocode guidance. The actual implementation must handle proptest's type constraints — `Box<dyn Normalizer>` is not `Debug`, so you may need wrapper types or index-based approaches where you construct the normalizers inside the test body from the indices rather than in the strategy.

**Simulation test scenarios:**

1. **`simulation_full_pipeline_never_panics`** (proptest, 256+ cases default)
   - Random normalizer subset (1-4)
   - Random tokenizer
   - Random Unicode input (`\\PC{1,200}`)
   - Assert: `process()` either succeeds or returns a well-typed error (no panic)

2. **`simulation_spans_always_valid`** (proptest, 256+ cases)
   - Random normalizer subset + tokenizer + input
   - If process succeeds: all token spans have `start <= end` and `end <= input.len()`
   - CharMapping `original_len()` matches `input.len()`

3. **`simulation_composed_mapping_consistent`** (proptest, 256+ cases)
   - Random normalizer subset + random input
   - If process succeeds and composed_mapping present:
     - `composed_mapping.original_len() == input.len()`
     - For each alignment `(orig, norm)`: `orig < input.len()` and `norm < normalized.len()`

4. **`simulation_token_text_resolvable`** (proptest, 256+ cases)
   - Random pipeline + input
   - If process succeeds: every token's StringId resolves via text_store

5. **`simulation_normalizer_chain_order_matters`** (proptest, 100 cases)
   - Pick 2+ normalizers, run pipeline in original and reversed order
   - Assert: both succeed or fail gracefully (no panic)
   - If both succeed: results may differ (order matters) — just verify validity

6. **`simulation_idempotent_double_process`** (proptest, 100 cases)
   - Process input once, then process the normalized output again with same pipeline
   - Assert: second pass doesn't panic, produces valid output

7. **`simulation_large_input_no_panic`** (proptest, 50 cases)
   - Generate large input (1000-5000 chars) with random Unicode
   - Random pipeline
   - Assert: completes without panic, within reasonable time
